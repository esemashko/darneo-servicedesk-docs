# Маршрутизация заявок

Пример адреса страницы: `https://example.com/helpdesk/settings/ticket_routing/`

Маршрутизация заявок нужна, чтобы ServiceDesk сам назначал ответственного сотрудника по условиям в заявке. Администратор задает правила, а система применяет их при создании или обработке заявки.

Раздел помогает убрать ручной выбор исполнителя там, где ответственный зависит от отдела, типа заявки, приоритета, компании, объекта обслуживания или дополнительных полей.

## Список

В списке видны правила маршрутизации. Каждое правило показывает условия, ответственного сотрудника, наблюдателей и статус.

![Список правил маршрутизации](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/automation/ticket-routing/list.png){ .ds-screenshot }

Правила проверяются сверху вниз. Более точные правила лучше ставить выше: например, сначала правило для конкретной компании и объекта, затем общее правило для сервисного отдела.

Статус можно переключить прямо в списке. Неактивное правило остается в настройках, но не участвует в назначении заявок.

## Форма правила

В форме правило собирается из двух частей: какие заявки нужно найти и кого назначить по найденной заявке.

![Форма правила маршрутизации](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/automation/ticket-routing/form.png){ .ds-screenshot }

В блоке условий можно выбрать:

- отдел в заявке
- тип заявки
- приоритет
- компанию
- объект обслуживания
- дополнительные поля

В блоке назначения выбирают ответственного сотрудника и, если нужно, наблюдателей.

Если условия не заполнены, правило подходит для любой заявки. Такое правило удобно держать внизу списка как общий вариант на случай, когда более точные правила не сработали.

## Когда нужен этот раздел

Открывайте маршрутизацию, когда заявки должны автоматически попадать к нужным сотрудникам. Например, обращения по кассовому узлу можно направлять в сервисный отдел, срочные инциденты отдавать отдельному ответственному, а заявки по конкретному объекту сразу назначать на закрепленного инженера.
