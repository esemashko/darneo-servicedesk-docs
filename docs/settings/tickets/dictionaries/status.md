# Статусы

Пример адреса страницы: `https://example.com/helpdesk/settings/ticket_status/`

Статусы описывают жизненный цикл заявки: новая, в работе, ожидает клиента, закрыта. По статусам сотрудники понимают, на каком этапе находится обращение.

В статусах также настраивают кнопки перехода, разрешенные переходы, автозакрытие и дополнительные требования при переводе заявки.

## Список

В списке видны названия статусов, цвет, текст кнопки перехода, автозакрытие и активность.

![Список статусов](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/dictionaries/status-list.png){ .ds-screenshot }

Порядок можно менять перетаскиванием строк. Активность управляет тем, доступен ли статус для работы.

## Форма статуса

В форме задают название, текст кнопки перехода, цвет и время автозакрытия.

![Форма статуса](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/dictionaries/status-form.png){ .ds-screenshot }

Текст кнопки должен описывать действие сотрудника. Например, для статуса `В работе` кнопка может называться `Передать на проверку`.

## Переходы

Для каждого статуса можно указать, в какие статусы разрешен переход.

![Переходы статуса](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/dictionaries/status-transitions.png){ .ds-screenshot }

Так можно ограничить случайные переходы. Например, из статуса `В работе` разрешить переход только в `Ожидает клиента` или `Закрыта`.

## Дополнительные настройки

В дополнительных настройках задают поведение при переводе заявки в выбранный статус.

![Дополнительные настройки статуса](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/dictionaries/status-settings.png){ .ds-screenshot }

Здесь можно включить автоназначение исполнителя, скрыть время нахождения в статусе, запросить трудозатраты или комментарий.

### Закрытие заявки специалистами

В настройках финального статуса есть поле **«Дополнительно разрешить закрытие заявки»**. Администратор может выбрать несколько условий:

- **Автору заявки** — специалисту, который создал заявку, в том числе от имени другого клиента
- **Ответственному за заявку** — специалисту, назначенному ответственным
- **Наблюдателю заявки** — сотруднику, добавленному в наблюдатели этой заявки

![Закрытие разрешено автору или наблюдателю](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/dictionaries/status-close-participants.png){ .ds-screenshot }

Достаточно одного совпадения. Например, при выборе автора и наблюдателя специалист сможет закрыть заявку, если создал её или наблюдает за ней. Если автор принял собственную заявку в работу, разрешение по авторству сохраняется.

У специалиста также должно быть право изменять эту заявку и её статус. Одного авторства при доступе только на чтение недостаточно. Переход в финальный статус должен быть разрешён из текущего статуса.

По умолчанию список пуст: **«Не разрешать специалистам»**. Чтобы отключить дополнительные разрешения, снимите все пункты и нажмите **«Сохранить»**.

![Дополнительные разрешения выключены](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/dictionaries/status-close-disabled.png){ .ds-screenshot }

Пустой выбор сохраняет прежние права клиента, руководителя и администратора. Он также не отключает автоматическое закрытие заявок.

Если удалить специалиста из наблюдателей или отключить разрешение после открытия карточки, при сохранении система снова проверит доступ. Ранее открытая форма не сохраняет отозванное право.


## Когда нужен этот раздел

Открывайте статусы, когда меняется процесс обработки заявок. Например, если нужно добавить этап согласования, сделать обязательный комментарий при закрытии или ограничить переходы между этапами.
