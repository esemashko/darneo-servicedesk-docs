# Настройка каналов уведомлений

Пример адреса страницы: `https://example.com/helpdesk/settings/notify/`

Каналы уведомлений настраиваются в разделе [Оповещения](../settings/tickets/general/notify.md). Здесь администратор выбирает, какие события отправлять пользователям и через какие каналы.

У каждого канала есть два уровня настройки.

1. В строке события нужно включить канал: например, Push для нового комментария или E-mail для смены статуса.
2. Для самого канала должны быть заполнены общие параметры и данные получателя.

## Список оповещений

В таблице видны события и каналы Push, Email, SMS, Telegram и MAX. Переключатель включает или выключает канал для конкретного события.

![Список оповещений](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/general/notify/list.png){ .ds-screenshot }

Если канал включен, ServiceDesk попробует отправить уведомление, когда произойдет это событие. Если канал выключен, сообщение по нему не уйдет, даже если все остальные настройки заполнены.

## Настройка события

Кнопка с шестеренкой открывает настройки сообщения для выбранного события и канала.

![Настройка события уведомления](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/general/notify/detail.png){ .ds-screenshot }

В форме можно настроить текст сообщения. Для Push и E-mail задаются заголовок и текст. Для SMS, Telegram и MAX задается текст сообщения. В описании параметров показаны переменные, которые можно использовать в шаблоне.

Для событий по статусам можно выбрать статусы, при которых нужно отправлять сообщение. Для напоминаний по срокам можно настроить время до плановой даты. Для просрочки можно настроить момент первой отправки, период повторов и ограничение количества сообщений.

## Push

Push — это внутреннее уведомление Bitrix. Для него не нужен внешний ключ или токен.

Чтобы Push пришел, нужно:

- включить Push у нужного события
- оставить заголовок и текст сообщения для этого события
- убедиться, что получатель является пользователем Bitrix
- убедиться, что на портале работает модуль мгновенных сообщений Bitrix

Push удобен для сотрудников, которые постоянно работают внутри портала. Например, ответственный видит новое назначение или новый комментарий без перехода в почту.

### Push на телефоне

Переключатель Push в этой таблице определяет, отправляет ли ServiceDesk уведомление по событию. Пользователь может отдельно отключить его показ в мобильном приложении Битрикс24. Откройте [инструкцию для мобильного приложения](../start/mobile-application.md), если нужно изменить эту настройку.

Чтобы Push пришел на телефон, включите канал для нужного события и убедитесь, что пользователь не отключил уведомления в мобильном приложении или настройках телефона.

## E-mail

E-mail отправляется на почту пользователя через почтовое событие Bitrix.

![Настройки E-mail](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/general/notify/email-settings.png){ .ds-screenshot }

Чтобы письмо пришло, нужно:

- включить E-mail у нужного события
- заполнить тему и текст письма для этого события
- указать общий заголовок писем в настройках модуля
- убедиться, что у получателя заполнена электронная почта
- убедиться, что на портале настроена отправка почты

E-mail подходит для важных событий, которые пользователь должен увидеть даже вне портала. Например, клиенту можно отправлять письмо о регистрации заявки и смене статуса.

## SMS

SMS отправляется через сервис sms.ru. ServiceDesk хранит ключ в параметре `API_KEY_SMSRU` и передает его в sms.ru как `api_id`.

![Настройки SMS](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/general/notify/sms-settings.png){ .ds-screenshot }

Чтобы SMS пришло, нужно:

- включить SMS у нужного события
- заполнить текст SMS для этого события
- указать ключ sms.ru в настройках модуля
- убедиться, что у получателя заполнен личный телефон
- проверить баланс и доступность SMS-сервиса

SMS лучше использовать только для действительно срочных событий. Например, для просроченной плановой даты решения или критичной заявки.

## Telegram

Telegram отправляется через бота. ServiceDesk использует token из параметра `API_KEY_TELEGRAM`, а получателя ищет в поле пользователя `UF_HELPDESK_TELEGRAM_ID`.

![Настройки Telegram](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/general/notify/telegram-settings.png){ .ds-screenshot }

Чтобы сообщение пришло в Telegram, нужно:

- включить Telegram у нужного события
- заполнить текст сообщения для этого события
- указать token Telegram-бота в настройках модуля
- заполнить Telegram ID у получателя
- убедиться, что пользователь может получать сообщения от этого бота

Telegram удобен для быстрых внутренних уведомлений, когда сотрудники чаще реагируют в мессенджере, чем в почте.

## MAX

MAX отправляется через MAX-бота и требует подключения webhook. ServiceDesk использует token из `API_KEY_MAX`, ник бота из `MAX_BOT_NAME`, публичный адрес из `MAX_PUBLIC_BASE_URL`, а получателя ищет по привязке пользователя к MAX.

В настройках MAX заполняют token, ник бота и публичный HTTPS URL сайта. После этого webhook нужно подключить. Секрет webhook создается автоматически при подключении.

![Настройки MAX](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/general/notify/max-settings.png){ .ds-screenshot }

Чтобы сообщение пришло в MAX, нужно:

- включить MAX у нужного события
- заполнить текст сообщения для этого события
- указать MAX token
- указать ник MAX-бота
- указать публичный HTTPS URL сайта
- подключить webhook в настройках MAX
- привязать пользователя к MAX в карточке сотрудника или клиента

Публичный HTTPS URL должен начинаться с `https://`. Он нужен, чтобы MAX мог отправлять события обратно в ServiceDesk. После подключения webhook в настройках канала должен появиться статус подключения.

Если пользователь еще не привязан к MAX, в его карточке нужно сгенерировать ссылку подключения и пройти привязку.

![Привязка пользователя к MAX](/darneo-servicedesk-docs/assets/screenshots/settings/tickets/general/notify/max-binding.png){ .ds-screenshot }

## Что проверить при ошибке

Если уведомление не приходит, проверяйте настройки по порядку.

1. Событие должно подходить пользователю. Например, клиент не получает приватные комментарии.
2. Канал должен быть включен в строке нужного события.
3. Текст сообщения должен быть заполнен.
4. У получателя должны быть заполнены данные для канала: почта, телефон, Telegram ID или привязка MAX.
5. У внешнего канала должны быть заполнены общие настройки: ключ SMS, token Telegram или параметры MAX.
