# Уведомления

Уведомления помогают не пропустить важные изменения по заявкам. Они приходят тем пользователям, которых событие касается: ответственному, наблюдателям, контактному лицу клиента или сотрудникам отдела.

Краткая схема работы простая: в заявке происходит событие, ServiceDesk определяет получателей и отправляет сообщение по включенным каналам.

## Каналы уведомлений

ServiceDesk поддерживает несколько каналов.

- **Push**: внутреннее уведомление в Bitrix
- **E-mail**: письмо на электронную почту пользователя
- **SMS**: сообщение на телефон пользователя
- **Telegram**: сообщение в Telegram
- **MAX**: сообщение в MAX

Один и тот же тип события можно отправлять сразу в несколько каналов. Например, ответственному можно оставить Push и E-mail, а SMS включать только для критичных событий.

Настройка каналов вынесена на отдельную страницу: [Настройка каналов](channel-settings.md).

## Какие события бывают

Уведомления связаны с жизненным циклом заявки.

### Создание и назначение заявки

Пользователь получает уведомление, когда ему назначили новую заявку или когда в заявке изменился ответственный.

Если заявка создана в отделе без ответственного, уведомление может прийти сотрудникам этого отдела. Так команда видит, что заявку нужно забрать в работу.

### Комментарии

Ответственный и наблюдатели могут получать уведомления о новом комментарии.

Клиент получает уведомление только по публичному комментарию. Приватные внутренние комментарии остаются внутри команды поддержки.

### Статусы и сроки

Уведомления могут приходить при смене статуса заявки и при изменении плановой даты решения.

Отдельно настраиваются напоминания о приближении плановой даты и уведомления о просрочке. Это удобно для контроля SLA: сотрудник видит, что срок скоро наступит или уже нарушен.

### Оценка заявки

Когда клиент добавляет оценку по заявке, уведомление может получить ответственный и наблюдатели. Это помогает быстро увидеть обратную связь по выполненной работе.

### Наблюдение за заявкой

Если пользователя добавили в наблюдатели, он может получить уведомление и дальше следить за изменениями по заявке.

## Кому приходят уведомления

Получатели зависят от события.

- **Ответственный** получает события по заявкам, за которые он отвечает
- **Наблюдатели** получают события по заявкам, за которыми следят
- **Клиент** получает события по своей заявке и публичной переписке
- **Сотрудники отдела** получают уведомление, если заявка попала в отдел без ответственного

ServiceDesk не отправляет уведомление пользователю о его же действии, если это действие не требует отдельного сообщения. Например, сотрудник, который сам оставил комментарий, обычно не получает уведомление о своем комментарии.

## Если уведомление не пришло

Сначала проверьте, должно ли событие вообще отправляться этому пользователю. Например, клиент не получает приватные комментарии, а наблюдатель не получает события по заявке, если он не добавлен в наблюдатели.

Затем проверьте настройки канала. Для письма у пользователя должна быть электронная почта, для SMS нужен телефон, для Telegram нужен Telegram ID, а для MAX нужна привязка пользователя к MAX.

Если не работает внешний канал, проверьте общую настройку канала. Для SMS нужен действующий ключ sms.ru, для Telegram — token бота, для MAX — token, ник бота, публичный HTTPS URL и подключенный webhook.

Если событие и канал настроены правильно, обратитесь к администратору ServiceDesk. Он проверит включение события, шаблон сообщения и общие настройки нужного канала.
