# Уведомления

Уведомления помогают не пропустить важные изменения по заявкам. Они приходят тем пользователям, которых событие касается: ответственному, наблюдателям, контактному лицу клиента или сотрудникам отдела.

Краткая схема работы простая: в заявке происходит событие, ServiceDesk определяет получателей и отправляет сообщение по включенным каналам.

## Каналы уведомлений

ServiceDesk поддерживает несколько каналов.

- **Push**: внутреннее уведомление в Bitrix
- **E-mail**: письмо на электронную почту пользователя
- **SMS**: сообщение на телефон пользователя
- **Telegram**: сообщение в Telegram
- **MAX**: сообщение в MAX

Один и тот же тип события можно отправлять сразу в несколько каналов. Например, ответственному можно оставить Push и E-mail, а SMS включать только для критичных событий.

## Настройка каналов

У каждого канала есть два уровня настройки.

1. В строке события нужно включить канал: например, Push для нового комментария или E-mail для смены статуса.
2. Для самого канала должны быть заполнены общие параметры и данные получателя.

Подробная таблица событий находится в разделе [Оповещения](settings/tickets/general/notify.md). Ниже перечислено, что требуется для каждого канала.

### Push

Push — это внутреннее уведомление Bitrix. Для него не нужен внешний ключ или токен.

Чтобы Push пришел, нужно:

- включить Push у нужного события
- оставить заголовок и текст сообщения для этого события
- убедиться, что получатель является пользователем Bitrix
- убедиться, что на портале работает внутренний модуль уведомлений Bitrix

Push удобен для сотрудников, которые постоянно работают внутри портала. Например, ответственный видит новое назначение или новый комментарий без перехода в почту.

### E-mail

E-mail отправляется на почту пользователя через почтовую систему Bitrix.

Чтобы письмо пришло, нужно:

- включить E-mail у нужного события
- заполнить тему и текст письма для этого события
- указать общий заголовок писем в настройках канала E-mail
- убедиться, что у получателя заполнена электронная почта
- убедиться, что на портале настроена отправка почты

E-mail подходит для важных событий, которые пользователь должен увидеть даже вне портала. Например, клиенту можно отправлять письмо о регистрации заявки и смене статуса.

### SMS

SMS отправляется через сервис sms.ru.

Чтобы SMS пришло, нужно:

- включить SMS у нужного события
- заполнить текст SMS для этого события
- указать `api_id` sms.ru в настройках канала SMS
- убедиться, что у получателя заполнен телефон
- проверить баланс и доступность SMS-сервиса

SMS лучше использовать только для действительно срочных событий. Например, для просроченной плановой даты решения или критичной заявки.

### Telegram

Telegram отправляется через бота.

Чтобы сообщение пришло в Telegram, нужно:

- включить Telegram у нужного события
- заполнить текст сообщения для этого события
- указать token Telegram-бота в настройках канала Telegram
- заполнить Telegram ID у получателя
- убедиться, что пользователь может получать сообщения от этого бота

Telegram удобен для быстрых внутренних уведомлений, когда сотрудники чаще реагируют в мессенджере, чем в почте.

### MAX

MAX отправляется через MAX-бота и требует подключения webhook.

Чтобы сообщение пришло в MAX, нужно:

- включить MAX у нужного события
- заполнить текст сообщения для этого события
- указать MAX token
- указать ник MAX-бота
- указать публичный HTTPS URL сайта
- подключить webhook в настройках MAX
- привязать пользователя к MAX в карточке сотрудника или клиента

Публичный HTTPS URL нужен, чтобы MAX мог отправлять события обратно в ServiceDesk. После подключения webhook в настройках канала должен появиться статус подключения. Если пользователь еще не привязан к MAX, ему нужно сгенерировать ссылку подключения в карточке и пройти привязку.

## Какие события бывают

Уведомления связаны с жизненным циклом заявки.

### Создание и назначение заявки

Пользователь получает уведомление, когда ему назначили новую заявку или когда в заявке изменился ответственный.

Если заявка создана в отделе без ответственного, уведомление может прийти сотрудникам этого отдела. Так команда видит, что заявку нужно забрать в работу.

### Комментарии

Ответственный и наблюдатели могут получать уведомления о новом комментарии.

Клиент получает уведомление только по публичному комментарию. Приватные внутренние комментарии остаются внутри команды поддержки.

### Статусы и сроки

Уведомления могут приходить при смене статуса заявки и при изменении плановой даты решения.

Отдельно настраиваются напоминания о приближении плановой даты и уведомления о просрочке. Это удобно для контроля SLA: сотрудник видит, что срок скоро наступит или уже нарушен.

### Оценка заявки

Когда клиент добавляет оценку по заявке, уведомление может получить ответственный и наблюдатели. Это помогает быстро увидеть обратную связь по выполненной работе.

### Наблюдение за заявкой

Если пользователя добавили в наблюдатели, он может получить уведомление и дальше следить за изменениями по заявке.

## Кому приходят уведомления

Получатели зависят от события.

- **Ответственный** получает события по заявкам, за которые он отвечает
- **Наблюдатели** получают события по заявкам, за которыми следят
- **Клиент** получает события по своей заявке и публичной переписке
- **Сотрудники отдела** получают уведомление, если заявка попала в отдел без ответственного

ServiceDesk не отправляет уведомление пользователю о его же действии, если это действие не требует отдельного сообщения. Например, сотрудник, который сам оставил комментарий, обычно не получает уведомление о своем комментарии.

## Что можно настроить

Администратор управляет уведомлениями в разделе [Оповещения](settings/tickets/general/notify.md).

Там можно настроить:

- какие события активны
- какие каналы использовать для каждого события
- заголовок и текст сообщения для Push и E-mail
- текст сообщения для SMS, Telegram и MAX
- переменные в тексте, например номер заявки, статус, ответственный или ссылка на заявку
- время напоминания до плановой даты решения
- правила повторных уведомлений при просрочке
- общие параметры каналов E-mail, SMS, Telegram и MAX

## Если уведомление не пришло

Сначала проверьте, должно ли событие вообще отправляться этому пользователю. Например, клиент не получает приватные комментарии, а наблюдатель не получает события по заявке, если он не добавлен в наблюдатели.

Затем проверьте настройки канала. Для письма у пользователя должна быть электронная почта, для SMS нужен телефон, для Telegram нужен Telegram ID, а для MAX нужна привязка пользователя к MAX.

Если не работает внешний канал, проверьте общую настройку канала. Для SMS нужен действующий ключ sms.ru, для Telegram — token бота, для MAX — token, ник бота, публичный HTTPS URL и подключенный webhook.

Если событие и канал настроены правильно, обратитесь к администратору ServiceDesk. Он проверит включение события, шаблон сообщения и общие настройки нужного канала.
